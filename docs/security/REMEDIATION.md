## Applying

Both migrations need explicit approval before they touch production (see the [runbook](MIGRATION-RUNBOOK.md)). Before applying: take a backup or confirm point-in-time recovery; re-run the read-only integrity counts (they were 0 on 2026-11-17). They are transactional; a failure leaves nothing applied. Record each in `supabase_migrations.schema_migrations` under its file version and name (AGENTS.md). After applying: run the Supabase security advisor and the isolation test against a replay of production's schema.

Rollback of `20261117130000`: drop the `zz_tenant_references_guard` and `zz_tenant_owner_immutable` triggers, the four `*_owned` path constraints, and the four `private` functions it adds — no data to restore. Rollback of `20261117140000`: recreate the previous select policy and unschedule `volteira-mcp-call-log-retention`; the scrubbed log content and deleted rows are not recoverable except from a backup (by design).
